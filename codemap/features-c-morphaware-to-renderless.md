For each: skip escaped `@@`, skip inside script/style, repair paren matching with `hasEvenNumberOfParentheses` (token_get_all) in a while loop (:120-149), then classify by `preg_match` against opening/closing/@empty/@continue-@break patterns (:153-161) and call prefix/suffix functions.

5. PERFORMANCE OBSERVATIONS
   - COMPILE-TIME vs RUNTIME split. Compile cost is paid only when a Blade view is (re)compiled (compiled view cache keyed by mtime/path), but it is registered on the GLOBAL blade compiler, so it runs for ALL app views/components/layouts, not just Livewire ones, and for every `Blade::render()` of an inline string (e.g. SupportPageComponents:164/186 renders a string template per page load; Laravel's Blade::render compiles a string to a temp file each call, UNSURE of exact Laravel version behaviour).
   - O(directives x template length): each opening/closing/loop directive match triggers `replaceMatchIfNotInsideAHtmlTag` which does `substr($template,0,pos)` + `substr($template,pos)` full-string copies (:496-497, :504) plus `$before.$prefix.$found.$suffix.$after` rebuild (:506), and `isInsideHtmlTag` does another `substr($template,0,$position)` (:519) and repeated `substr($before,0,$searchFrom)` + `strrpos` inside a while loop (:526) and `substr($before,$bracketPos)` (:532). Net: roughly O(N_directives x L) string copying, plus the backward `<` scan can be O(#`<` before position) per directive (quadratic worst case on large templates).
   - Each directive does 2-4 `preg_match` against patterns constructed at call time with `preg_quote` of the entire found text including its expression (:169, :201-205, :255, :287-298, :314, :342-346); the pattern is then run on `$after` (rest of the template) with ungreedy flags `mUi` (:499) - it only needs a match at offset 0 but the regex is unanchored, so on a non-match it scans the remaining template (cost up to O(L) per directive). UNSURE whether a match always exists at offset 0 (if it does, cost is small).
   - Regex objects rebuilt on every compile: `directivesPattern` x2 per template (:75-76, uses collect()->sortBy/map/join over ~12-20 items), `isLoop`/`isEndLoop` rebuild their patterns every call (:353-360, :365-375), `findIgnoredTagRanges` builds its pattern per template (:432-437) and runs 1-2 extra `preg_match` per tag found (:450, :455). preg's internal cache softens repeated identical patterns, but the PHP string building is repeated.
   - `token_get_all('<?php '.$match)` per match whose regex-captured text ends in `)` but fails the quick check (:402-405, loop :120-149): only for nested-paren expressions; tokenization per candidate. Also `str($match[0])->endsWith(')')` constructs a Stringable per match per loop iteration (:122).
   - `\Livewire\invade($compiler)->conditions` (:53) runs on every compile of every template: creates a reflection wrapper each time (UNSURE exact cost, invade() lives in helpers.php) and rebuilds the `$directives` array merging custom conditions each compile.
   - First regex `/\B@(@?\w+(?:::\w+)?)([ \t]*)(\( ( [\S\s]*? ) \))?/x` (:82) matches EVERY `@directive` in the file (including non-conditional ones like @include, @click, email-like text excluded by \B) and the lazy `[\S\s]*?` with `)` can backtrack across large spans for unbalanced parens. Same shape as Laravel's own compileStatements so it roughly doubles that scan.
   - RUNTIME cost (every render of a compiled view, hot path): each injected marker is emitted as `<?php if(\Livewire\Mechanisms\ExtendBlade\ExtendBlade::isRenderingLivewireComponent()): ?>MARKER<?php endif; ?>` (:171-173, 225-227 etc.). So every @if/@endif/@foreach/@endforeach/@forelse/@empty/@break/@continue executes 1 static method call (`! empty(static::$livewireComponents)`, ExtendBlade.php:33-36) per directive per execution; inside loops it runs per iteration (loops emit `startLoopIteration()` guarded call per iteration, closing emits `endLoop()`). For a list rendering N rows with M nested conditionals this is O(N*M) extra static calls, plus each emitted `<!--[if BLOCK]><![endif]-->` / ENDBLOCK adds bytes to HTML sent to the client and nodes for the JS morph to process. SupportCompiledWireKeys::openLoop/startLoopIteration/endLoop/closeLoop do the work (out of scope, other agent).
   - Output size: 2 comments per conditional (BLOCK+ENDBLOCK ~54 bytes) per execution, including per loop iteration for nested @if. Affects response HTML size, snapshot-independent.
   - `config()` read only at provide()/flush-state (:19-24), fine. Note `flush-state` re-reads config but does NOT re-register/unregister the precompiler (if config toggled after boot only the statics change).
