## 4. Unusual things I noticed

1. **Custom `App\Attributes\Computed`** (app/Attributes/Computed.php) extends Livewire's Computed to add a per-instance memo for `persist:`/`cache:` computeds because BaseComputed::handleMagicGet skips its in-request memoization and hits `Cache::remember` (Redis round trip + unserialize) on **every access** when persist/cache is set. That is a framework-level inefficiency the app already patched around, and a good core candidate: memoize in BaseComputed even when persist/cache is on. 663 uses, an unknown share with persist/cache.
2. **Morph-marker comments are fighting the table.** The team already special-cased `@if` in table.blade.php:254 because markers break key-matching between rows. A core option for skipping marker injection in loops that carry `wire:key` (or exposing per-view opt-out) would help every x-table page without app changes.
3. **`wire:key` density on Orders Manage is 4 per row, none on data-row `td`s**; morph matching relies on tr keys. Per-row Alpine scopes (4) + custom directive `x-empire-line-header` (3) are initialized by Alpine's mutation observer after each morph; the team built `morph.updating` skip + `data-row-hash` to avoid re-init (PR #1001 area).
4. **Snapshot of the Orders Manage root carries a per-row 16-field array** (`ordersManageSidebarData.lines`) and entangled `selected`/`expanded`; every request pays for dehydrating/hydrating/diffing it. Synthetic fixtures should include this (I can produce one).
5. **Expanded row child hydrates ~9 Eloquent model props per request** (ModelSynth), is `#[Lazy]`, is the biggest Blade view (65KB template), and "Expand All" can create up to perPage (≤200) of them. Core relevance: ModelSynth hydration cost, lazy bundling, per-component snapshot checksum/serialize cost × N children in one response.
6.
