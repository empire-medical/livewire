## 4. Update payload and client diff
- Each request body = `{_token, components:[{snapshot, updates, calls}, ...]}`.
  - `snapshot`: the FULL last-known server snapshot as an encoded JSON string (`component.snapshotEncoded`), re-sent every time (only the `"children"` memo is rewritten by regex). Includes data tuples with synth metadata, memo, checksum. Size scales with component state; large public properties are re-uploaded on every action. (The server needs it for checksum verification/hydration.)
  - `updates`: flat dotted-path map from `diffAndConsolidate(canonical, ephemeral)` (only changed properties, plus `queuedUpdates` from `$set`).
  - `calls`: array of `{method, params, metadata}`.
  - Bundled children (reactive props/modelable) add their own full snapshots with a `$commit` call.
- `canonical` (last server state, plain data) vs `ephemeral` (live client state; `reactive` is `Alpine.reactive(ephemeral)`). `getUpdates()` walks canonical vs ephemeral recursively EVERY send, comparing every key (utils.js:223-347). `left === right` shortcut only for identical references; since canonical and ephemeral are separate deep clones, every nested object is walked (O(total nodes)). On size change, `deeplyEqual` (2x JSON.stringify) per root key at root (288); consolidation uses `dataGet(rootRight, path)` (re-parses dotted path from root).
- `mergeNewSnapshot` (component.js:71-97) per response, for each component: `JSON.parse(snapshotEncoded)` (again; index.js:451 already parsed once), `deepClone(this.canonical)` (stringify+parse of whole state), `applyUpdates` (dataSet per update key), `extractData(deepClone(snapshot.data))` x3 (lines 77, 87, 89; three separate JSON round trips of the new data, each followed by the recursive `extractData` mutation), `diff(updatedOldCanonical, newCanonical)` for `dirty` (the deprecated diff with spread at utils.js:198; result `dirty` is returned and, in the request/index.js call at 469, the return value is DISCARDED), then `diffAndPatchRecursive(updatedOldCanonical, newData, this.reactive)` which uses `deeplyEqual` per key per level and triggers Alpine reactivity only for changed leaves. Note `this.ephemeral` is not rebuilt; patches go through the reactive proxy.
  So per response the full data tree is JSON-stringified/parsed ~5 times, plus the snapshot parsed twice (once in index.js:451, once in component.js:72), plus snapshot string (potentially large) assigned onto the DOM `wire:snapshot` attribute in morph.js:25 on every morph.

## 6. Debouncing / bundling summary
- wire:model.live: client debounce default 150ms (wire-model.js, not in scope), then `$set` -> 5ms buffer in messageBus.
- Same-component same-scope actions inside the 5ms window (or while pending) are merged into a single Message (`findScopedPendingMessage`), identical actions squashed by fingerprint.
- Different components' pending messages are bundled into a single HTTP request unless isolated or lazy-isolated; components with reactive/modelable children bundle those children's `$commit` messages into the same request (interactions.js:23-44).
- In-flight: later actions on same scope are deferred until previous request finishes (action.defer + onFinish refire) except async, model.live (parallel + superseding), polls (dropped).
- `callAndClearComponentDebounces` (debounce.js:41) flushes debounced model updates before click actions.
